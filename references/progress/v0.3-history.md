# Catshand v0.1–v0.3 — Development History

This document records the development history of catshand from its initial commit through version 0.3.6, synthesized from the git log and code review. It serves as institutional memory for the modernization effort starting at v0.4.0.

---

## Timeline

### 2023-07-20 — Project Established

Initial commits established the project scaffolding: README, conda environment YAML, and the basic package structure under `src/catshand/`. The project goal was defined: automate repetitive audio editing tasks for the Tripod Cat's Podcast team using Python and Audacity.

### 2023-07-31 — Core CLI Shape

`main.py` was established using `argparse` as the entry point. The subcommand pattern (`prjinit`, `audio2wav`, etc.) was set early. Folder-searching utilities were added to support locating audio files across project directories.

### 2023-08-13 — File Discovery Fix

Fixed a regression in folder searching that had broken file discovery when project directories were nested. This was an early sign that the ad-hoc dict/string approach to paths was fragile.

### 2023-08-18 — README and Usage Docs

First full README pass documenting the two-phase workflow (pre-editing → post-editing), Audacity prerequisites, and OpenAI API key setup. Included shell command examples for both Mac and Windows.

### 2023-10-16 — CLI Shell Scripts

Added `CLI/postedit_multitrack.sh` and `CLI/postedit_singletrack.sh` as wrapper scripts for the post-editing pipeline, making the common workflows invocable in a single command.

### 2023-12-27 — postproc Fix

Bug fix in `postproc.py` affecting file dictionary generation. The issue was in how output paths were constructed when processing multi-host recordings.

### 2024-03-01 — OpenAI API Update (v0.3.3 → v0.3.4)

Updated `openai_api.py` to the v1.x client (`openai>=1.13.3`). The old `openai` package had a breaking API change (from `openai.ChatCompletion.create` to `client.chat.completions.create`). Added `tiktoken` for token counting prior to API calls to manage cost.

### 2024-03-03 — Version 0.3.4 → 0.3.5 → 0.3.6 (same day)

Several rapid version bumps on 2024-03-03:
- **0.3.4 → 0.3.5**: Project restructuring — new `tools/` submodule layout, separating each CLI command into its own file.
- **0.3.5 → 0.3.6**: README updates, corrected installation steps, added Google Drive links for demo audio materials.

This was the most active single-day development period. The `tools/` split was the biggest structural change in v0.3.x.

### 2024-03-06 — OpenAI Refinement

Follow-up commit to `openai_api.py` refining the audio segmentation logic and multiprocessing behavior for transcription of long episodes.

### 2024-10-16 — Audacity Pipe Bug Identified

Two commits on this date document a discovered regression:
- `48a7392` — "in the process of fixing audacity pipe": active debugging of the Audacity named-pipe protocol.
- `aeb66c3` — "bug identified": confirmed that Audacity 3.6.4 introduced a breaking change to the scripting pipe. **Workaround: roll back to Audacity 3.6.1.** (Tracked in upstream issue #7293.)

This issue was left open — `audacitypipe.py` and `audacitytool.py` were not fully fixed as of v0.3.6.

### 2024-12-14 — main.py Update

`main.py` updated to align with the tools/ submodule layout from March. Likely fixing import paths after the module restructure.

### 2025-01-06 — Tooling Modernization (Config Cleanup)

Four commits on 2025-01-06:
- Updated `.gitignore` to exclude more cache/build artifacts.
- Removed/updated VSCode launch configuration.
- Updated `mypy.ini`, `pytest.ini`, and `ruff` settings in `pyproject.toml` to current best practices.
- Updated README with corrected Audacity version warning.

## State at v0.3.6 (January 2025)

### What Works
- Pre-editing pipeline: `audio2wav` (format conversion + normalization + noise reduction), `silrm` (silence removal), `audiosplit` (timestamp-based splitting).
- Post-editing pipeline: `trackmerger`, `audmerger` (spatial audio).
- Transcription: `prjsummary` using OpenAI Whisper API with multiprocessing.
- Project initialization: `prjinit` with interactive config prompts.

### Known Issues at Handoff
1. **Audacity pipe broken on 3.6.4+** — `audacitypipe.py` and `audacitytool.py` have an unresolved bug when running against Audacity 3.6.4. Affects `audacitypipe` and `audacitypipe_prjpre` subcommands.
2. **`multiprocessing` fork issues** — `audio2wav.py`, `postproc.py`, and `openai_api.py` use `multiprocessing` with the default `fork` start method, which is unreliable on macOS with some native libraries (librosa/numpy). Can cause silent hangs.
3. **No type annotations** — most modules lack type hints; mypy is configured but catches few errors.
4. **Test coverage near-zero** — `tests/` (configured in `pytest.ini`) was empty; only `test/test_array.py` existed as a standalone script, not a proper pytest test.
5. **Mixed CLI frameworks** — `main.py` uses argparse, `main_dev.py` uses Typer. Inconsistent command signatures.
6. **Config as plain dicts** — JSON configs loaded directly into dicts with no schema validation.

## Motivation for v0.4.0 Modernization

The v0.3.x codebase reached a functional plateau but accumulated technical debt that makes further development difficult:

1. The fork-based multiprocessing is the root cause of the most common hangs.
2. Untyped configs make refactoring error-prone.
3. Two CLI frameworks in the same package create user confusion.
4. Conda environment management is slow and the YML files have diverged.

v0.4.0 addresses these systematically via the choices documented in [spec.md](../../../spec.md).
